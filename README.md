# claude-docker

Run [Claude Code](https://docs.claude.com/en/docs/claude-code/overview) in a Docker sandbox that can only see your
current project folder, with the `grill-me` and `grill-with-docs` skills preinstalled and a separate Python
environment that never touches your host `.venv`.

Built for Ubuntu and the terminal of PyCharm Community Edition, but it works from any terminal.

> **Note:** This repository is intended for my private use. It was completely generated by
> [Claude Code](https://claude.com/claude-code) using the `grill-me` skill, which interviews the user about a plan
> before any code is written. It is an unofficial helper script, not affiliated with or endorsed by Anthropic; the
> skills are third-party ([mattpocock/skills](https://github.com/mattpocock/skills)). It comes with no support or
> guarantees. The sandbox reduces but does not remove risk (see
> [What is isolated, and what is not](#what-is-isolated-and-what-is-not)), so use it at your own risk.

## Features

- **Only your project is visible.** The current directory is mounted as `/workspace`. No home directory,
  SSH keys, Docker socket or other projects.
- **Safe defaults.** Runs as a non-root user with your UID/GID (files stay owned by you), all Linux
  capabilities dropped, `no-new-privileges`, PID limit.
- **`.env` files stay hidden.** `.env` and `.env.*` files in the project root (`.env.local`, `.env.production`, ...)
  appear empty and read-only inside the container, so Claude cannot read or change them. Templates such as
  `.env.example` stay visible.
- **Separate Python environment per project**, managed by [uv](https://docs.astral.sh/uv/) and stored in a Docker
  volume outside the project. Your host `.venv` stays untouched and keeps working.
- **Skills included:** `grill-me` and `grill-with-docs` (plus the helper skills they appear to rely on).
- **One file.** The script generates its own Dockerfile and builds the image on first use.

## Requirements

- Ubuntu (other Linux distributions are likely fine but untested)
- Docker Engine, and your user in the `docker` group
- Internet access (Docker registries, npm, GitHub, Anthropic API)
- A Claude account (subscription login) or an `ANTHROPIC_API_KEY`

After adding yourself to the `docker` group (`sudo usermod -aG docker "$USER"`), log out and back in.
Until then, `docker` commands fail with "permission denied".

## Installation

Get the script by cloning this repository (use the clone URL shown on the repository page) or by downloading
`claude-docker` on its own. In a clone the script is already executable, so copy it somewhere on your `PATH`:

```bash
mkdir -p ~/.local/bin
cp claude-docker ~/.local/bin/
```

Or symlink it, so that a `git pull` updates the installed script:

```bash
ln -s "$PWD/claude-docker" ~/.local/bin/claude-docker
```

If you downloaded the file on its own, make it executable first (`chmod +x claude-docker`).

Make sure `~/.local/bin` is on your `PATH` (it is by default on Ubuntu once the directory exists and you have
logged in again). Alternatively, call the script by its full path.

The first start builds the image, which takes a few minutes.

## Usage

Run it **from your project root** (never `source` it):

```bash
cd ~/projects/my-project
claude-docker
```

On the first start, log in with `/login` inside Claude Code and open the printed URL in your host browser.
Alternatively, export `ANTHROPIC_API_KEY` on the host before starting; it is passed into the container.

Inside Claude Code, start a skill with `/grill-me` or `/grill-with-docs`.

| Command                                        | What it does                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------- |
| `claude-docker`                                | Start Claude Code in the sandbox                                    |
| `claude-docker <args>`                         | Pass any further arguments to `claude`                              |
| `claude-docker --rebuild`                      | Rebuild the image (latest Claude Code and skills, no cache)         |
| `claude-docker --shell`                        | Open bash instead of Claude (the Python environment is active)      |
| `claude-docker --reset-env`                    | Delete this project's Python environment (recreated on next start)  |

The options above must come first, before any arguments meant for `claude`.

The script refuses to run in `/` or in your home directory, so the sandbox can never see more than a project.

## PyCharm

No Docker plugin is needed. Open the built-in terminal (Alt+F12, it starts in the project root) and run
`claude-docker`. Do not use PyCharm's *External Tools* for this: Claude Code needs an interactive TTY.

## Python environment

The environment lives in a per-project Docker volume mounted at `/home/claude/pyenv` and is created by uv on the
first start.

**uv version:** the image contains the same uv version as your host, so lockfile handling and `uv sync` behave
the same inside and outside the container. The version is taken from `CLAUDE_UV_VERSION` if set, otherwise from
`uv --version` on the host, and falls back to `latest` if no host uv is found. When the host's uv version
changes, the image is rebuilt automatically on the next start.

**Python version**, first match wins:

1. `CLAUDE_PYTHON` environment variable (e.g. `3.12`)
2. `.python-version` in the project
3. The version recorded in the project's `.venv/pyvenv.cfg` or `venv/pyvenv.cfg`
4. `python3` on the host
5. uv's default

If the requested version changes, the environment is recreated.

**Dependencies** are installed at start-up, but only when the dependency files changed:

- `uv.lock` + `pyproject.toml`: `uv sync --frozen` (never modifies `uv.lock`)
- `requirements*.txt` (also in `requirements/`): `uv pip install -r ...`
- `setup.py`, `setup.cfg`, or a `pyproject.toml` with `[project]` / `[tool.poetry]`: `uv pip install -e .`

**Keeping everything runnable outside the container:**

- The host `.venv`/`venv` is hidden inside the container (an empty tmpfs is mounted over it), so Claude can
  neither see nor damage it.
- `PYTHONDONTWRITEBYTECODE` is set, so no `__pycache__` folders appear in the project.
- The sandbox contains a `CLAUDE.md` (rewritten on every start) that tells Claude not to create a `.venv` in the
  project and to record every new dependency in `requirements.txt` / `pyproject.toml`. Anything installed only
  with `pip install` exists only in the sandbox.
- Editable installs can leave a `*.egg-info` folder in the project. It is normally covered by `.gitignore`.

## Skills

The image build clones [mattpocock/skills](https://github.com/mattpocock/skills) and installs these skills:

- `grill-me`, `grill-with-docs` (required; the build fails if they are not found)
- `grilling`, `domain-modeling` (helper skills these two appear to rely on; a missing one only produces a warning)

Skills are copied into the sandbox configuration on every start. Because they come from a third-party
repository, pin a specific commit for reproducible and reviewable builds:

```bash
SKILLS_REF=<commit-sha> claude-docker --rebuild
```

`grill-with-docs` writes documentation such as `CONTEXT.md` and ADRs into your project. Review the changes with Git.

To use different skills, edit the `SKILLS` variable at the top of the script and rebuild.

## Configuration

| Variable                 | Effect                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| `CLAUDE_PYTHON`          | Force a Python version, e.g. `3.12`                                                          |
| `CLAUDE_SKIP_ENV_SYNC=1` | Skip setting up the Python environment entirely (no Python is available in that case)       |
| `SKILLS_REF`             | Branch, tag or commit of the skills repository (default: `HEAD`); used when building         |
| `CLAUDE_DEBUG=1`         | Trace the container start-up (`set -x`) to see why a start fails                             |
| `CLAUDE_UV_VERSION`      | uv version for the image, e.g. `0.8.4` or `latest` (default: the uv version found on the host) |
| `CLAUDE_EXPOSE_DOTENV=1` | Do not hide `.env` / `.env.*` files (e.g. if tests inside the sandbox need their values)      |
| `ANTHROPIC_API_KEY`      | If set on the host, passed into the container                                                |

Your global Git `user.name` and `user.email` are passed in so commits work inside the container. No Git or SSH
credentials are available there, so pushing from inside the container is not possible by design.

Further customization (apt packages, base image, resource limits) means editing the generated Dockerfile and
`docker run` options inside the script. After changing the Dockerfile part, bump `IMAGE_VERSION` in the script or
run `claude-docker --rebuild`.

## What is isolated, and what is not

| Isolated                                            | Not isolated                                                      |
| --------------------------------------------------- | ----------------------------------------------------------------- |
| Host filesystem outside the project folder          | **Network:** the container has normal outbound internet access    |
| Host `.venv` / `venv` (hidden in the container)     | **Project contents:** everything else in the folder              |
| Docker socket, SSH keys, host `~/.claude`           | Files Claude changes in the project are changed for real          |
| `.env` / `.env.*` files in the project root         |                                                                   |

This is filesystem isolation for convenience and damage limitation, not a hardened security boundary.

- Hidden are the regular files `.env` and `.env.*` **in the project root**, except the templates
  `.env.example`, `.env.sample`, `.env.template` and `.env.dist` (change the list via `DOTENV_TEMPLATES` at the top
  of the script). Symlinks and file names containing `:` are not hidden (the script prints a warning).
- Not hidden: `.env` files in subfolders (e.g. `backend/.env`), `.envrc`, and any other secrets such as key files.
  Claude can read those and could send them over the network.
- Because the hidden files are empty inside the sandbox, code that needs their values fails there. Start with
  `CLAUDE_EXPOSE_DOTENV=1` if you accept Claude seeing them.
- Membership in the `docker` group is effectively root-equivalent on the host. Rootless Docker avoids that.
- `--dangerously-skip-permissions` works inside the container, but given the points above it is not a risk-free mode.
- Claude's login and settings live in the Docker volume `claude-code-sandbox-config`, not in your real `~/.claude`.

## Updating and cleaning up

```bash
claude-docker --rebuild                          # newest Claude Code and skills
claude-docker --reset-env                        # this project's Python environment

docker volume rm claude-code-sandbox-config      # log out / reset Claude settings
docker volume ls --filter name=claude-pyenv      # all per-project Python environments
docker images claude-code-sandbox                # image versions (old ones can be removed with docker rmi)
```

The image tag contains a version (`claude-code-sandbox:v<N>`). When a new script version raises it, the image is
rebuilt automatically on the next start, and so is the image when the host's uv version no longer matches the one
inside it. The in-container auto-updater is disabled; use `--rebuild` to update Claude Code and the skills.

To check the versions inside the image:

```bash
docker run --rm --entrypoint uv claude-code-sandbox:v1 --version
docker run --rm --entrypoint claude claude-code-sandbox:v1 --version
```

Replace `v1` with the current tag (see `IMAGE_VERSION` in the script).

## Troubleshooting

| Problem                                              | Fix                                                                                             |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `permission denied` when the script calls `docker`   | Add yourself to the `docker` group, then log out and back in (or run `newgrp docker`)           |
| Terminal closes when running the script              | Run `claude-docker`; do not `source` it or wrap it in an alias that does                        |
| Container exits immediately                          | Start with `CLAUDE_DEBUG=1 claude-docker` and read the output                                   |
| A package fails to build                             | The image ships `build-essential`; for other system libraries add apt packages in the script and run `--rebuild` |
| Wrong Python version                                 | Set `CLAUDE_PYTHON` or add a `.python-version` file                                             |
| Dependencies broken or outdated                      | `claude-docker --reset-env`, or `claude-docker --shell` to investigate                          |
| `--reset-env` says the volume is in use              | Exit any running `claude-docker` session for that project first                                 |
